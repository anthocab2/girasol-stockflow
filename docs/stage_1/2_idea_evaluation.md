# Task 2 - Idea Evaluation

## Project

**Hotel Girasol Stock Flow**

## Evaluation Criteria

The project ideas were evaluated according to:

### Feasibility

Can a functional MVP realistically be built within the available development period?

### Potential Impact

How much practical value could the application provide?

### Technical Alignment

Does the project provide meaningful practice with software engineering technologies and concepts?

### Scalability

Could the project support additional functionality in later versions?

### Real-World Value

Does the project address a specific operational problem?

Each category was scored from 1 to 5.

* **1 - Poor**
* **2 - Weak**
* **3 - Average**
* **4 - Good**
* **5 - Excellent**

# Hotel Girasol Stock Flow

## Strengths

* Addresses an observed real-world problem.
* Manual inventory verification can take approximately 40 minutes.
* Has clearly identifiable users.
* Provides measurable project goals.
* Provides product traceability.
* Strong alignment with Python backend development.
* Requires meaningful database design.
* Can be implemented incrementally.
* Has opportunities for future expansion.

## Weaknesses

* Inventory accuracy depends on transactions being recorded correctly.
* Digital inventory may differ from physical inventory if product movements are not registered.
* Employees need a simple and efficient interface.
* Initial inventory values must be accurate.

## Risks

* Incorrect quantities
* Invalid transactions
* Unauthorized access
* Database inconsistencies
* Multiple employees interacting with inventory
* Scope becoming too large
* Employees forgetting to record transactions

## Constraints

* Individual developer
* Limited project development time
* Need to prioritize the MVP
* Need to design both frontend and backend
* Need to test inventory logic carefully

# Hotel Maintenance Tracker

## Strengths

* Solves a recognizable hotel problem.
* Could improve maintenance organization.
* Technically feasible.
* Supports priorities and statuses.

## Weaknesses

* Similar systems already exist.
* Could become a generic issue tracker.
* Provides less differentiation.

## Risks

* Notification systems could increase complexity.
* Assignment workflows could expand the scope.

## Reason for Rejection

The maintenance system was considered useful, but Hotel Girasol Stock Flow addresses a more specific observed workflow and offers a clearer measurable benefit.

# Employee Shift Task Manager

## Strengths

* Relatively simple to implement.
* Easy to understand.
* Could improve employee organization.
* Can track task completion.

## Weaknesses

* Similar to many existing task-management systems.
* Lower differentiation.
* Less closely connected to the main operational problem identified.

## Risks

* Could become a generic to-do application.
* Scope could expand into scheduling and workforce management.

## Reason for Rejection

The concept was technically feasible, but Hotel Girasol Stock Flow provides greater real-world value and a stronger software engineering challenge.

---

# Final Evaluation

Hotel Girasol Stock Flow received the highest score:

**24/25**

It was selected because it provides the strongest combination of:

* Feasibility
* Potential impact
* Technical relevance
* Real-world value
* Future scalability

The project will therefore move forward with Hotel Girasol Stock Flow as the final MVP concept.
